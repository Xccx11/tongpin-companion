# 同频家庭群 V2 设计

## 目标

把群聊从多名角色并列回答用户，升级为接近真实家庭群的多人关系场景。多个恋人围绕用户互动，可以自然接话、轻微吃醋、争宠、互相调侃和沉默。群聊与私聊双向流动，但不泄露私聊原文或未经允许的敏感细节。

## 明确决策

- 采用家庭群摘要层，不让群聊直接读取任何私聊原文。
- 群聊内容可回流至每名参与角色的私聊，且保留群聊来源。
- 群聊可以基于完整的群内上下文主动自然说话，不要求针对用户；它不发送系统通知，且与私聊共用暂停、静默、冷却、去重和事实边界。
- 群聊和私聊、动态配图共用全局单一图片生成队列，严格一次只生成一个任务。
- 所有群聊生图仍需用户确认，支付、银行、密码、认证和系统安全设置永久拒绝。

## 数据模型

新增 `FamilyGroupFact`：

- `id`、`groupThreadId`、`ownerCharacterId`、`summary`、`sourceThreadId`、`sourceKind`、`createdAt`、`expiresAt`、`sensitivity`、`allowedInGroup`。
- 仅保存一条可共享关系事实，不保存私聊原句、照片路径或模型原始上下文。
- 来源为角色自己的私聊或群聊；群聊来源事实可供该群的所有成员私聊检索。
- 支持用户查看、编辑、删除和禁止群聊提及。删除后同步删除对应的可检索群聊记忆。

新增 `GroupMemberState`：

- `groupThreadId`、`characterId`、`attention`、`affection`、`jealousy`、`unspokenIntent`、`lastSpokeAt`。
- 状态仅影响群内发言节奏和语气，不会被当作用户现实事实，也不直接显示为模型分析。

## 家庭群摘要与回流

私聊完成后，记忆复盘可提出摘要候选。只有通过本地结构校验且 `allowedInGroup=true` 的摘要才进入对应家庭群。默认可共享的内容是作息、已说出的计划、公开承诺、群成员可合理知道的关系进展；默认排除私聊原文、图片、私密身体信息、系统感知原始数据、角色秘密和用户禁止提及的内容。

每次角色私聊时，检索范围是该角色自己的私聊记忆，加上她所属群聊中相关的真实群消息片段和群聊摘要。模型会收到明确来源标记，例如“家庭群内发生：...”，不能把它改写成两人私聊经历。未加入该群的角色没有任何访问路径。

清空群聊会删除群消息、群内共同片段、相关家庭群摘要和由该群回流形成的私聊检索项。清空私聊不会删除仍在群内有效的独立事实。删除角色时清除其群成员状态和私有摘要，不影响其他成员。

## 群聊编排

用户每次群聊发言启动一次 `GroupTurnDirector`：

1. 收集最近群消息、成员卡、家庭群摘要、群成员状态、@ 提及和当前氛围。
2. 输出一个有序发言计划：主说话者一名，至多两名自然接话者，其他成员沉默。
3. 主说话者先生成回复；接话者读取同一轮前序回复后再各自生成，因此能对彼此做出真实反应。
4. `@角色` 强制被提及角色进入计划首位，其他成员仅在有真实反应价值时加入。
5. 每个角色只使用她可见的私聊、群聊和家庭群摘要。禁止复制私聊原文、编造用户经历、围攻、羞辱、施压或机械全员回复。

氛围配置：

- `安静`：通常一人回复，极少接话。
- `日常`：一名主回复者，偶尔一名接话者。
- `热闹`：一名主回复者，至多两名接话者，角色间互动和轻微争宠概率更高。

轻微吃醋、抢话、替用户说话和玩笑只能是角色自身情绪，不能否定用户选择、制造内疚或变成冲突升级。

## 动态互通

动态是共享社交场景。角色发布动态后，其他角色可由模型决定点赞、评论或忽略。用户评论时，原作者优先有机会针对该条评论回复，其他成员也可决定是否加入；每个角色对同一条用户评论最多回复一次。所有评论使用 `replyToCommentId` 呈现为“角色 回复 你/角色”，而不是平铺状态文本。

## 群聊图片

群成员可以在群聊中提议发图，也可以响应用户的明确图片请求。提议必须显示确认卡，展示发起角色和简短的自然说明。确认后任务进入 `ImageGenerationQueue`：

- 队列覆盖私聊、群聊和动态配图，FIFO 严格单并发。
- 每个任务持久化，状态为 `PENDING`、`QUEUED`、`RUNNING`、`SUCCEEDED`、`FAILED` 或 `REJECTED`。
- 排队任务在原会话显示“排队中”；运行任务显示“正在生成”；成功后在原线程由发起角色发送图片；失败保留失败结果和真实原因摘要。
- 单角色图使用该角色外貌提示词、参考图和当前群聊场景。多人同框图明确列出参与角色，并为每人分别组装身份锚点和当前场景限制。
- 群内图片是群聊事实，可被参与成员在私聊中以群聊来源提及；图片二进制不自动嵌入无关角色的私聊上下文。

## 界面与管理

群管理页包含：群名、头像、成员添加/移除/排序、家庭群氛围、家庭群摘要列表和群聊图片任务状态。聊天页保持现有微信式目录，群聊行显示未读数、最后发言者和简短预览。`@` 选择器按成员头像和名称展示。群聊图片确认、排队、生成和失败状态都在消息流原位置更新。

## 失败处理与验证

- 群聊导演或任一成员模型调用失败时，不影响已经持久化的前序成员消息；仅跳过该成员并记录可脱敏诊断。
- 编排结果非法、成员被删除、群已清空或上下文版本变化时取消剩余成员发言。
- 图片队列在网络中断、进程重启和后台恢复时从持久任务继续；不重复提交已取得网关任务 ID 的图片。
- 测试覆盖：私聊原文不泄露、群聊回流仅限成员、清空同步遗忘、@ 优先、三档氛围、发言上限、角色动态互相参与、回复归属、单并发生图、任务恢复与多角色同框提示词组装。
